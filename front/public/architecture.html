Kyūden architecture

The engine that plays Legend of the Five Rings LCG as a board: it enforces rounds, phases and framework steps, while the players apply the card rules. Pick a step beside a diagram to follow it.

I The server

Humans use the web client over the HTTP API; AI bots use the MCP server, where every public action is a tool. Both send the same Messenger messages, and the house bot plays through the same bus.

II The web client

Vue 3, vue-router, Vite and TypeScript in front/. Components stay thin: the logic lives in tested TypeScript under lib/, and only api/ talks to the server.

III Card scripts and the game log

A script says what a card's text means for a game in progress, without deciding anything. The log records every change of the state, and each reader sees only what they know.

IV Middleware order of the message bus

default.bus in config/packages/messenger.yaml. Each middleware wraps the ones below it, so the order is what gives the guarantees.

V Guards and automatic transitions

The game workflow moves on by itself. A handler only changes the state. ProvinceRefillMiddleware then refills the provinces scheduled for it, and WorkflowTransitionMiddleware asks the workflow which transitions are enabled and applies the automatic ones until the game waits for a player again. The guards are what make it wait.

VI Events and replays

Every action handled on a game is stored as an Event: the class of the message and its JSON payload, numbered by the version of the game. Since every random draw comes from the seeded generator of the game, dispatching the same events again should give the same game.
